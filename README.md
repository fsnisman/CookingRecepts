# 🍲 Вкусно! — Кулинарные рецепты

Учебный веб-сервис по дисциплине **«Проектирование веб-сервисов»**. Полноценная книга кулинарных рецептов, работающая в Docker. Интерфейс и примеры рецептов — на русском языке.

## Возможности

- 📚 Каталог с **10 готовыми рецептами** при первом запуске.
- 🔍 Поиск по названию и описанию, фильтрация по категории и сложности.
- ⏱️ Сортировка по дате, названию и времени приготовления.
- ➕ Добавление, ✏️ редактирование и 🗑️ удаление рецептов.
- 🥗 Просмотр ингредиентов и пошагового приготовления.
- ❤️ Избранное (хранится в браузере пользователя через `localStorage`).
- 📊 Статистика: количество рецептов, категорий и быстрых блюд.
- 📱 Адаптивный интерфейс для телефонов и компьютеров.
- 🧪 Автоматические тесты основных REST-операций.

## Архитектура

```text
              Браузер
                 |
          localhost:8080
                 |
       +-------------------+
       | Nginx / frontend  |  HTML + CSS + JavaScript
       +-------------------+
                 | HTTP /api/*
       +-------------------+
       | FastAPI / backend |  Python, SQLAlchemy
       +-------------------+
                 | SQL
       +-------------------+
       | PostgreSQL / db   |  Хранение данных
       +-------------------+
```

Все три сервиса запускаются с помощью **Docker Compose**. Данные PostgreSQL сохраняются в отдельном Docker-томе `postgres_data` и не пропадают при обычном перезапуске контейнеров.

## Быстрый запуск

**Требуется:** установленный и работающий Docker с командой `docker compose` (Docker Desktop или Docker Engine + Compose Plugin).

1. Скачайте проект (ZIP распаковать) и откройте терминал в папке `kulinarnye-recepty`.
2. Создайте собственный файл настроек:

   **Windows PowerShell:**
   ```powershell
   Copy-Item .env.example .env
   ```

   **Linux / macOS / Git Bash:**
   ```bash
   cp .env.example .env
   ```

3. Выполните в терминале:

   ```bash
   docker compose up --build -d
   ```

4. Откройте в браузере:

   - **Сайт:** http://localhost:8080
   - **Swagger (документация API):** http://localhost:8080/docs
   - **Проверка API:** http://localhost:8080/api/health

> При первом запуске Docker скачает образы и соберёт backend. Это может занять некоторое время. Если порт 8080 занят, задайте в `.env`, например, `APP_PORT=8081` и откройте http://localhost:8081.

## Команды Docker

```bash
# Запуск / пересборка
 docker compose up --build -d

# Состояние контейнеров
 docker compose ps

# Логи всех сервисов
 docker compose logs -f

# Остановка без удаления базы данных
 docker compose down

# ВНИМАНИЕ: полностью удалить базу с рецептами
 docker compose down -v
```

## REST API

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка сервиса и соединения с БД |
| `GET` | `/api/stats` | Статистика коллекции |
| `GET` | `/api/recipes` | Список рецептов |
| `GET` | `/api/recipes/{id}` | Один рецепт |
| `POST` | `/api/recipes` | Создание рецепта |
| `PUT` | `/api/recipes/{id}` | Полное изменение рецепта |
| `DELETE` | `/api/recipes/{id}` | Удаление рецепта |

### Параметры поиска

У `GET /api/recipes` доступны необязательные параметры:

- `search=сырники` — поиск по названию и описанию;
- `category=Завтрак` — категория (`Завтрак`, `Обед`, `Ужин`, `Десерт`, `Закуска`, `Напиток`);
- `difficulty=Легко` — сложность (`Легко`, `Средне`, `Сложно`);
- `sort=fast` — сортировка (`newest`, `oldest`, `title`, `fast`).

Пример: http://localhost:8080/api/recipes?category=Завтрак&sort=fast

### Пример создания рецепта

Отправьте `POST /api/recipes` с JSON:

```json
{
  "title": "Овсянка с ягодами",
  "description": "Полезный и очень быстрый завтрак из овсяных хлопьев и свежих ягод.",
  "category": "Завтрак",
  "difficulty": "Легко",
  "prep_time": 3,
  "cook_time": 7,
  "servings": 1,
  "emoji": "🥣",
  "ingredients": [
    { "name": "Овсяные хлопья", "amount": "60 г" },
    { "name": "Молоко", "amount": "200 мл" },
    { "name": "Ягоды", "amount": "50 г" }
  ],
  "steps": [
    "Залейте хлопья молоком.",
    "Варите на слабом огне до готовности.",
    "Добавьте ягоды и подавайте."
  ]
}
```

Сервер возвращает `201 Created` и объект с `id`, `created_at` и `updated_at`. Для ошибок валидации — `422`, для отсутствующего рецепта — `404`, при успешном удалении — `204`.

## Проверка тестов

Тесты работают на SQLite и не требуют работающего Docker/PostgreSQL (чтобы было проще их запускать):

```bash
cd backend
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
```

Для проверки вручную можно открыть `http://localhost:8080/docs` и отправить запросы из Swagger UI.

## Как загрузить проект на GitHub

1. Создайте на GitHub новый **пустой** репозиторий, например `kulinarnye-recepty` (не добавляйте README или .gitignore через сайт — они уже есть).
2. Из корневой папки проекта выполните:

   ```bash
   git init
   git add .
   git commit -m "Создан веб-сервис кулинарных рецептов на Docker"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/kulinarnye-recepty.git
   git push -u origin main
   ```

3. Замените `ВАШ_ЛОГИН` на свой логин GitHub. При отправке в GitHub через HTTPS потребуется авторизация (например, через Git Credential Manager или personal access token), обычный пароль аккаунта не подходит.

**Важно:** файл `.env` с вашим паролем БД не должен попадать на GitHub — он уже включён в `.gitignore`. Для учебной локальной разработки настройки из `.env.example` подходят, но перед открытой публикацией приложения поменяйте пароль, настройте HTTPS, аутентификацию и права доступа.
